# คู่มือการร่วมเขียนเนื้อหา (Contribution Guide)

TaiChi112 ถูกสร้างขึ้นบนปรัชญาของ "องค์ความรู้ที่เกิดจากความร่วมมือ" (Collaborative Knowledge) ทุกหน้าบนแพลตฟอร์มนี้สามารถถูกแก้ไขและพัฒนาได้โดยคอมมูนิตี้ ไม่ว่าคุณจะต้องการ สร้าง, อ่าน, อัปเดต, หรือ ลบ (CRUD) เนื้อหา เรายินดีรับการมีส่วนร่วมของคุณเสมอ!

## 🤝 วิธีร่วมพัฒนาเนื้อหา

เราใช้ระบบ GitHub Pull Request ซึ่งเป็นมาตรฐานสากลสำหรับการอัปเดตเนื้อหาทั้งหมด

1. **ค้นหาหน้าที่ต้องการ:** หากคุณกำลังอ่านเนื้อหาแล้วพบคำผิด หรือมีข้อมูลที่มีประโยชน์อยากเพิ่มเติม ให้คลิกที่ปุ่ม **Edit on GitHub** (มักจะอยู่ด้านบนของหน้า)
2. **Fork และ Edit:** ระบบจะพาคุณไปยัง GitHub ซึ่งคุณสามารถ Fork พื้นที่จัดเก็บ (Repository) และทำการแก้ไขเนื้อหาได้โดยตรงผ่านไวยากรณ์ Markdown / MDX
3. **ส่ง PR:** เมื่อคุณพอใจกับการแก้ไขแล้ว ให้กดส่ง Pull Request (PR)
4. **รอการตรวจสอบ:** ผู้ดูแลระบบจะทำการตรวจสอบ PR ของคุณ อาจมีข้อเสนอแนะให้ปรับแก้เล็กน้อย และเมื่อเรียบร้อย เนื้อหาของคุณจะถูกผสาน (Merge) เข้าสู่ฐานความรู้หลักทันที!

## มาตรฐานการเขียนเนื้อหา

เพื่อรักษาคุณภาพของเนื้อหาให้อยู่ในระดับสูงเสมอ กรุณาปฏิบัติตามแนวทางต่อไปนี้:

- **Strict MDX:** ใช้ไวยากรณ์ GitHub Flavored Markdown มาตรฐาน หากต้องการจัดเลย์เอาต์ที่ซับซ้อน ให้ใช้ Component ของ Fumadocs UI ที่มีให้
- **ความชัดเจน:** เขียนคำอธิบายให้กระชับ ชัดเจน และคงความเป็นวิชาการในส่วนที่จำเป็น
- **Single Source of Truth (SSOT):** หากคุณแก้ไขคอนเซปต์ที่มีการอ้างอิงถึงในหน้าอื่นๆ ต้องแน่ใจว่าได้เสนอขอแก้ไขเอกสารที่เชื่อมโยงกันนั้นด้วย
- **การตรวจสอบ (Validation):** ตรวจสอบการแสดงผลบนเครื่องของคุณเอง (Local) ทุกครั้งก่อนส่ง PR

> [!TIP]
> หากคุณไม่แน่ใจเกี่ยวกับการเพิ่มเนื้อหาเชิงสถาปัตยกรรมขนาดใหญ่ หรือหมวดหมู่ใหม่ทั้งหมด คุณสามารถเปิด GitHub Issue เพื่อพูดคุยและสอบถามก่อนเริ่มเขียนเนื้อหาได้เสมอครับ
