# การจัดการข้อมูลระบุตัวตนและการเข้าถึง (IAM)

สรุปแนวคิดพื้นฐานของการจัดการข้อมูลระบุตัวตนและการเข้าถึง

## การยืนยันตัวตน (Authentication) vs. การอนุญาต (Authorization)

*   **การยืนยันตัวตน (AuthN):** กระบวนการตรวจสอบว่าผู้ใช้หรือระบบคือ *ใคร* (เช่น การตรวจสอบชื่อผู้ใช้และรหัสผ่าน, ข้อมูลทางชีวมิติ, การยืนยันตัวตนแบบหลายปัจจัย)
*   **การอนุญาต (AuthZ):** กระบวนการกำหนดว่าผู้ใช้หรือระบบที่ได้รับการยืนยันตัวตนแล้วได้รับอนุญาตให้ทำ *อะไร* (เช่น การตรวจสอบว่าผู้ใช้มีสิทธิ์อ่านหรือเขียนไฟล์เฉพาะเจาะจงหรือไม่)

## แนวคิดหลัก

### JWT (JSON Web Token)
*   รูปแบบที่กะทัดรัดและปลอดภัยสำหรับการแสดงสิทธิ์เพื่อส่งผ่านระหว่างสองฝ่าย
*   ประกอบด้วยสามส่วน: Header, Payload (สิทธิ์), และ Signature
*   ไร้สถานะ (Stateless): เซิร์ฟเวอร์ไม่จำเป็นต้องเก็บข้อมูลเซสชัน ข้อมูลที่จำเป็นทั้งหมดอยู่ในโทเค็น
*   มักใช้สำหรับการยืนยันตัวตนแบบ Bearer

### OAuth (Open Authorization)
*   มาตรฐานเปิดสำหรับการมอบหมายสิทธิ์การเข้าถึง
*   อนุญาตให้ผู้ใช้ให้สิทธิ์แอปพลิเคชันบุคคลที่สามเข้าถึงทรัพยากรของตนโดยไม่ต้องเปิดเผยข้อมูลประจำตัว (รหัสผ่าน)
*   ขั้นตอนที่พบบ่อย: Authorization Code Flow, Client Credentials Flow, Implicit Flow
*   มักใช้ Access Token เพื่อให้สิทธิ์

### RBAC (Role-Based Access Control)
*   วิธีการอนุญาตที่กำหนดสิทธิ์การเข้าถึงให้กับบทบาทเฉพาะแทนที่จะเป็นผู้ใช้แต่ละราย
*   ผู้ใช้จะได้รับมอบหมายบทบาท (เช่น ผู้ดูแลระบบ, บรรณาธิการ, ผู้ชม)
*   ช่วยลดความซับซ้อนในการจัดการในองค์กรขนาดใหญ่ เนื่องจากมีการอัปเดตสิทธิ์ในระดับบทบาท
